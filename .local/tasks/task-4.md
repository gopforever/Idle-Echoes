# LLM Game Master — AI-Driven World Content

## What & Why
Wire OpenAI into the game to act as a dynamic game master: generating contextual quest lines, writing NPC dialogue, narrating boss fights, and giving ghost players AI-authored voices. This transforms static game content into a living, responsive story engine that reacts to each player's specific race, class, zone, and history. Uses Replit's built-in AI integrations (no API key required, billed to Replit credits).

## Done looks like
- A full quest log page exists with 3–5 active quests generated by AI, specific to the player's current zone, class, level, and faction standing
- Each quest has: AI-written title + description + lore paragraph, 2–3 concrete objectives (kill X enemies in this zone, reach Y faction standing, collect Z item type), tracked progress, and a reward (XP, gold, specific item, AA XP)
- Completing a quest objective auto-detects during combat ticks and marks it complete; a new quest is generated to replace it
- NPC dialogue: clicking the shop merchant or a faction vendor opens a small dialogue panel with AI-written contextual flavor ("Ah, a Kerra Dirge from Maj'Dul. I don't see many of your kind here in Qeynos. What can I do for you?")
- Boss encounters add AI-generated taunts/flavor text to the combat log when the fight begins and when the boss dies
- Ghost players in the World feed now have AI-authored "quotes" — short in-character lines attributed to each ghost that appear in the world event feed alongside their actions
- A "Lore" tab on the character page shows an AI-generated biography for the player's character based on their race, class, alignment, and current accomplishments

## Out of scope
- Voice/audio (text only)
- Persistent multi-turn conversation memory beyond a single session
- AI-controlled gear decisions or crafting for ghost players
- Quest UI beyond the quest log page (no map markers, no world indicators)

## Tasks
1. **OpenAI integration setup** — Provision the Replit AI integration for OpenAI, copy the server-side template package into the monorepo, add it as a dependency in the API server, run migrations for any new schema tables needed (quest log table), update tsconfig project references.

2. **Quest generation engine** — Add a `quests` DB table (id, title, description, lore, objectives jsonb, rewards jsonb, status, generated_at). Create a `POST /quests/generate` endpoint that calls OpenAI with the player's context (zone, race, class, level, faction standings, kill history) to generate 3 contextually appropriate quests. Include a system prompt that enforces EQ2 lore accuracy, Norrathian setting, and objective types tied to the existing game systems.

3. **Quest progress tracking** — In the combat tick handler, check active quest objectives after each enemy kill or event (kill objectives, faction objectives checked on faction updates). Add `GET /quests` and `PATCH /quests/:id/complete` endpoints. Auto-generate a replacement quest when one is completed.

4. **Quest log UI** — New `/quests` route with a full quest log panel: active quests as cards with title, lore text (collapsed by default), objective checklist with progress bars, and reward preview. A "Generate New Quest" button calls the generate endpoint and shows a loading state. Completed quests shift to a faded "Completed" section below.

5. **NPC dialogue** — Add a `POST /npc/dialogue` endpoint that accepts an NPC type (merchant, faction_vendor, quest_giver) and player context, returns a short 2–3 sentence greeting. Wire this to shop and faction pages — a "Talk" button opens a small speech bubble overlay showing the AI response with a brief loading spinner.

6. **Boss encounter narration** — In the combat tick handler, when combat starts against a boss enemy, call OpenAI to generate a 1–2 sentence dramatic intro line and insert it into the combat log. When the boss dies, generate a brief victory line. Use a fast model (gpt-5-nano) and cache per boss ID so the same boss always has the same intro line.

7. **Ghost player voices + character lore** — Add a `GET /world/player/:id/quote` endpoint that returns (and caches) a short in-character quote for a ghost player, generated from their race/class/name. Attach these to world event feed entries. Add a `GET /character/lore` endpoint that generates (and caches in DB) a 3-paragraph biography for the real player's character.
